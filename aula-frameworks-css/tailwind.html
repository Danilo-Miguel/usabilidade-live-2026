0. Antes de tudo: como ler o nome de uma classe

Uma classe Tailwind quase sempre é montada assim: {propriedade}-{eixo/lado opcional}-{valor}. Por exemplo, px-4 se decompõe em p (propriedade = padding) + x (eixo = horizontal) + 4 (valor = índice 4 da escala de espaçamento). Vamos abrir cada peça.

0.1 Prefixos de propriedade mais comuns

Prefixo Propriedade CSS

text-color (cor do texto) OU font-size, dependendo do valor
border-border (cor/estilo da borda)
ppadding (espaço DENTRO do elemento, entre a borda e o conteúdo)
mmargin (espaço FORA do elemento, entre ele e os vizinhos)

Repare que text- serve para DUAS coisas (cor OU tamanho) — o Tailwind decide pelo valor: text-blue-600 é cor (tem um tom de cor depois), text-xl é tamanho (tem um "tamanho de camiseta" depois). Isso não é exclusividade do Tailwind: no CSS puro, color e font-size também são propriedades diferentes.

0.2 Letras de eixo/lado (depois de p e m)

Isto responde a pergunta "o que é px, o que é py": px e py AQUI não são a unidade "pixel" — são a propriedade p (padding) + uma letra de eixo. É só uma coincidência de abreviação com a unidade CSS px (que também existe, ver 0.5).
Letra Significa Exemplo

bbottom (embaixo)pb-2 = padding-bottom
lleft (esquerda)ml-2 = margin-left
rright (direita)pr-2 = padding-right
xeixo horizontal = esquerda + direita ao mesmo tempopx-4 = padding-left E padding-right
yeixo vertical = topo + embaixo ao mesmo tempopy-2 = padding-top E padding-bottom
(nenhuma)todos os 4 lados de uma vezp-4 = padding nos 4 lados

0.3 O que é rem?

rem = "root em": uma unidade de medida RELATIVA ao tamanho de fonte do elemento raiz da página (a tag <html>). No navegador, esse tamanho raiz é 16px por padrão (o usuário pode mudar isso nas configurações de acessibilidade do navegador/sistema). Então: 1rem = 16px, 0.5rem = 8px, 2rem = 32px — SE o usuário não tiver alterado a configuração padrão.

Por que usar rem em vez de px para espaçamento e fonte? Porque rem RESPEITA a preferência de tamanho de fonte do usuário (importante para acessibilidade — alguém com baixa visão que aumenta a fonte padrão do navegador vê todo o site crescer proporcionalmente); um valor fixo em px ignoraria essa preferência. Existe também o em, parecido, mas relativo ao elemento PAI (não à raiz), o que pode compor de forma imprevisível quando há elementos aninhados — por isso o Tailwind usa rem como padrão.

0.4 A escala numérica de espaçamento (o "4" de px-4)

O número depois do hífen NÃO é a quantidade de pixels nem de rem diretamente — é o ÍNDICE de uma escala pré-definida pelo Tailwind. Essa escala é usada em p-*, m-*, gap-*, w-*, h-*, etc.

Ou seja: px-4 = padding horizontal de 1rem (16px, assumindo fonte padrão) de cada lado. py-2 = padding vertical de 0.5rem (8px) em cima e embaixo.

0.5 Cuidado: existe um "px" que É de fato "1 pixel"

Para complicar um pouco: além do px/py de EIXO (item 0.2), o Tailwind também tem, na escala de tamanho, uma chave especial literalmente chamada px que significa "exatamente 1 pixel" — usada sozinha (sem eixo antes), como em w-px (width: 1px). São dois usos diferentes da mesma palavra "px"; o contexto (se vem logo depois de p/m como eixo, ou sozinha como tamanho) resolve a ambiguidade. Nesta aula não usamos w-px, mas é bom saber que existe.

0.6 A escala de cor (o "800" de text-gray-800)

Isto responde a pergunta "800 é peso?": NÃO. Em uma classe de cor (bg-, text-, border- seguidos do nome de uma cor), o número de 50 a 900 é o TOM/INTENSIDADE daquela cor — quanto MAIOR o número, mais ESCURA/saturada a cor fica. Não tem nenhuma relação com peso de fonte (isso é outra escala, item 0.7). Veja a escala do cinza renderizada de verdade abaixo:

50 = quase branco, 900 = quase preto. 500 costuma ser o tom "padrão/vívido" daquela cor. Isso vale para QUALQUER cor da paleta (blue-100... blue-900, red-100...red-900, etc.) — cada uma tem sua própria escala de 50 a 900.

0.7 A escala de peso da fonte (outra escala, com NOMES, não números)

Peso de fonte no CSS puro é numérico (100 a 900) — mas o Tailwind expõe isso via NOMES (font-bold), exatamente para você não confundir com o número de tom de cor do item 0.6. Por baixo dos panos, cada nome corresponde a um número de font-weight:
Classe Tailwind font-weight no CSS puro
font-thin100
font-light300
font-normal400 (padrão)
font-medium500
font-semibold600
font-bold700
font-extrabold800
font-black900

Ou seja: font-extrabold POR BAIXO DOS PANOS usa o mesmo número "800" que text-gray-800 usa para tom de cor — mas são duas escalas completamente independentes que só coincidem em usar múltiplos de 100. No class você nunca escreve font-800; sempre usa o nome (font-extrabold).

0.9 Play CDN (o que estamos usando nesta aula) x Instalação local (produção)

O <script src="https://cdn.tailwindcss.com"> no <head> desta página é chamado de Play CDN. Ele é perfeito para uma aula, mas o próprio Tailwind recomenda NÃO usá-lo em um site publicado de verdade. Veja a diferença:
Aspecto Play CDN (esta aula) Instalação local (produção)
Setup1 linha de <script>npm install + arquivo de config
O que o visitante baixaUm compilador JavaScript inteiro, que roda no navegador dele a cada visitaSó um arquivo .css estático, já pronto
Tamanho finalMaior (o compilador é pesado)Menor (só as classes que você realmente usou)
Customização (cores/fontes próprias)LimitadaTotal, via arquivo de configuração
Cache do navegadorRuim (recompila a cada carregamento)Ótimo (arquivo estático, cacheável)
Indicado paraAula, prototipagem rápidaSites e produtos publicados de verdade

Os comandos para configurar a versão de produção (não rodamos isso hoje, é só para vocês verem como é):

npm install -D tailwindcss postcss autoprefixer
npx tailwindcss init -p

Isso cria um tailwind.config.js, onde você diz quais arquivos o Tailwind deve "vigiar" para saber quais classes existem:

// tailwind.config.js
module.exports = {
  content: ["./src/**/*.{html,js}"],
  theme: { extend: {} },
  plugins: [],
}

Um arquivo CSS de entrada com 3 diretivas especiais:

/* src/input.css */
@tailwind base;
@tailwind components;
@tailwind utilities;

E o comando de build, que gera o CSS final estático (sem JavaScript nenhum sobrando para o visitante):

npx tailwindcss -i ./src/input.css -o ./dist/output.css --watch

2. Grid responsivo

O Tailwind não tem col-8/col-4 prontos como o Bootstrap. Em vez disso, usamos CSS Grid de verdade: grid-cols-N define quantas colunas existem AGORA, e prefixos como md: mudam esse número por tamanho de tela. Redimensione a janela para ver mudar de 1 para 3 colunas.
grid-cols-1 md:grid-cols-3
grid-cols-1 md:grid-cols-3
grid-cols-1 md:grid-cols-3
col-span-8 (66%)
col-span-4 (33%)

3. Espaçamento: p-* e m-*

Mesmo padrão de nome do Bootstrap ({p ou m}{lado}-{tamanho}), mas com escala numérica mais granular: cada índice da escala equivale a um valor em rem (unidade relativa à fonte raiz do navegador, normalmente 16px — ver Seção 0.3/0.4 para a explicação completa e a tabela de conversão). p-4 = 1rem (16px), p-8 = 2rem (32px).
p-0 (padding zero)
p-2 (padding pequeno)
p-8 (padding grande)
mt-8 (margin-top grande, empurra este bloco pra baixo)
largura fixa (w-52)
mx-auto -> centralizado
